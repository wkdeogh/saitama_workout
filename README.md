# 싸이따마훈련소

푸쉬업·스쿼트·기타운동·달리기 기록, 월별 캘린더, Three.js 캐릭터 성장. 모바일 우선 웹 앱입니다. Vercel에서 호스팅하고 Firebase Authentication과 Firestore를 사용합니다.

- Google 또는 카카오 로그인 후 최초 접속 시 캐릭터 이름(1~20자)을 입력합니다. 이름과 운동 기록은 계정에 저장되며 설정에서 이름을 변경할 수 있습니다.
- 신규 계정의 기본 목표: 푸쉬업·스쿼트·기타운동 각각 100개, 달리기 10km. 설정에서 목표를 저장하면 오늘의 훈련과 오늘 저장된 기록의 목표에 즉시 반영합니다. 운동량과 EXP는 바뀌지 않으며 과거 날짜의 목표·달성 상태는 유지합니다. 예전 기본값(50·50·0·0)을 그대로 쓰던 계정은 다음 접속 시 오늘 목표부터 한 번만 새 기본값으로 전환합니다. 이후 개인이 다시 변경한 목표는 그대로 유지합니다. 목표와 관계없이 실제 운동량으로 EXP를 얻습니다.
- 날짜별 실제 횟수와 거리(0.1km 단위) 입력·수정·삭제. 달성 여부는 그 날짜에 저장된 목표로 계산합니다.
- Google 또는 카카오 로그인이 필수입니다. 운동 기록과 이름은 Firestore에 계정별로 저장하고, `localStorage`의 `saitama-training:v1:account:{uid}`에 동기화 기준과 함께 캐시합니다. 비로그인 기록을 자동으로 가져오지 않습니다.
- 하단 메뉴는 훈련소·운동 기록·성장 도감·친구입니다. 계정 연결과 동기화, 운동 목표 설정은 상단에서 엽니다.
- 이름 설정을 마친 로그인 사용자는 자동으로 랭킹에 등록됩니다. 캐릭터 이름, 레벨, EXP와 종목별 누적 운동량이 다른 로그인 사용자에게 공개됩니다. 누적(기본 탭)·주간(한국 시간 월요일 시작) EXP 상위 50명, 동점은 공동 순위입니다. 1~3위에는 금·은·동 트로피가 표시되며 레벨을 크게, EXP를 작게 표시합니다. 순위는 EXP 기준입니다. 사용자 행이나 내 캐릭터 요약을 누르면 캐릭터와 누적 운동량 팝업이 열립니다. 이메일과 날짜별 기록은 랭킹에 공개하지 않습니다.
- iOS 홈 화면용 180px 아이콘, Android용 192/512px 아이콘과 웹 앱 매니페스트를 포함합니다.

## 성장 규칙

레벨 1에서 시작하여 **100 EXP마다 1레벨 상승**, 최대 **1000레벨**입니다.

- 푸쉬업·스쿼트·기타운동: 1회 = 1 EXP
- 달리기: 0.1km = 2 EXP (5km = 100 EXP, 10km = 200 EXP)
- 예: 푸쉬업 50회 + 스쿼트 50회 = 100 EXP, 1 → 2레벨. 여기에 기타운동 50회 + 달리기 5km를 더하면 250 EXP, 1 → 3레벨(50 EXP 이월).
- 기존 버전 1 기록도 실제 운동량 기준으로 자동 환산합니다. 추가 종목은 0으로 전환하며 과거 목표 달성은 유지합니다. 새 데이터는 버전 2를 사용합니다.

마지막 운동 이후 **연속 미기록 5일째 1레벨 하락, 이후 매일 1레벨씩 추가 하락**, 최저 1레벨입니다. 기록한 당일은 공백에 포함하지 않습니다. 예: 9월 1일 운동 후 9월 6일까지 미기록이면 −1레벨. 9월 6일 운동하면 공백은 4일이므로 해당 감소는 취소됩니다. 9월 7일에 재개하면 중간 5일 공백으로 감소가 유지됩니다. 6일 공백이면 −2레벨, 10일 공백이면 −6레벨입니다. 운동 재개 후에는 5일 유예 기간이 다시 시작됩니다. 네 종목 중 1 EXP 이상 기록하면 미기록 기간이 초기화됩니다. 전부 0인 기록은 운동으로 계산하지 않습니다.

다음 레벨까지 쌓은 EXP 나머지는 하락해도 유지됩니다. 최고 레벨에서는 초과 EXP를 비축하지 않습니다. 기록 수정·삭제·복원 시 모든 이력을 날짜순으로 다시 계산합니다. 누적 EXP는 운동량 총합이므로 레벨 감소와 관계없이 유지됩니다. 기기의 로컬 날짜를 사용합니다.

1레벨은 작은 키와 가는 팔다리로 시작하며 매 레벨 키·어깨·팔다리가 성장합니다. 가슴 근육(20), 복근(30), 등과 승모근(45), 빛 입자와 바닥 링(60), 에너지 링(80), 전신 번개(120), 주먹 에너지(150), 이중 링(175)를 해금합니다.

200부터 머리카락이 자라며 삼중 링이 생깁니다. 손목 보호대(250), 솟은 머리와 수련 반바지(350), 주황 바지와 푸른 부츠(450), 허리띠와 매듭(550), 도복 상의(650), 금빛 머리(750), 금발 각성(850), 최종 첨탑 머리와 사중 링(1000)으로 진화합니다. 머리 길이와 체격은 중간 레벨에서도 연속적으로 변화합니다.

성장 도감의 단계를 누르면 팝업으로 외형을 확인합니다. 잠긴 단계는 어두운 실루엣으로 가리고, 현재 레벨로 해금한 단계만 선명하게 표시합니다. 자유로운 레벨별 미리보기는 제공하지 않습니다. 동일한 WebGL 렌더러를 재사용하며 화면 밖과 숨겨진 탭에서는 렌더링을 멈춥니다. 동작 줄이기 설정에서는 이펙트를 정지된 상태로 표시합니다.

## 개발

Node.js 24.x 사용. Vercel Functions와 로컬 개발의 런타임을 동일하게 유지합니다.

```sh
npm ci
npm run dev
npm run check
```

`npm test`는 기록, 날짜, 백업, 레벨, 계정 병합과 랭킹을 검증합니다. `npm run test:rules`는 Java 21 이상이 필요하며 Firestore 에뮬레이터에서 계정 격리, Google 인증 필수, 랭킹 쓰기 검증을 수행합니다. `npm run build` 출력은 `dist/`입니다.

## 배포

서비스 주소: https://saitama-workout.vercel.app/

Vercel 프로젝트 `saitama-workout`은 GitHub `wkdeogh/saitama_workout`의 `main`에 연결되어 자동 배포합니다. `vercel.json`에서 `npm run check`로 테스트 후 `dist/`를 배포합니다. Vercel의 `VERCEL=1` 환경에서는 앱 경로가 `/`이고 로컬 개발은 기존 `/saitama_workout/` 경로를 유지합니다. Firebase 공개 웹 설정은 코드에 포함되어 별도 환경 변수 없이 운영합니다. `.env.example`의 에뮬레이터 설정을 프로덕션에 등록하지 마세요.

GitHub Actions는 Firestore 규칙 테스트와 앱 테스트·빌드를 수행하고, 기존 Pages 주소에는 `pages-migration/`의 이동 안내만 배포합니다. 기존 주소 https://wkdeogh.github.io/saitama_workout/ 는 8초 후 새 주소로 이동합니다. Firebase 프로젝트와 사용자 UID가 같으므로 서버 기록을 이전할 필요는 없습니다. 새 주소에서는 다시 로그인해야 하며 홈 화면 앱은 새 주소에서 다시 추가합니다. 도메인별 로컬 캐시는 공유되지 않으므로 미동기화 기록은 이전 브라우저에서 먼저 동기화해야 합니다.

## 계정과 동기화

같은 계정으로 로그인하면 서버에 저장된 기록을 불러옵니다. 수정은 기기에 먼저 저장한 후 서버 트랜잭션으로 동기화합니다. 서로 다른 날짜의 수정은 합치고, 같은 날짜를 동시에 수정하면 마지막 동기화의 변경이 우선합니다. 실패하면 기기 기록을 보존하고 설정/친구 탭의 동기화 버튼으로 재시도합니다. 동기화가 끝나기 전 브라우저 데이터를 삭제하지 마세요. JSON 내보내기·가져오기는 제공하지 않습니다. 시크릿 브라우저에서는 기록이 유지되지 않을 수 있습니다. 네트워크 없이 앱을 다시 여는 오프라인 캐시는 별도로 제공하지 않습니다.

잘못된 기기 저장 데이터를 감지하면 덮어쓰기를 막습니다. 다른 브라우저에서 같은 계정으로 로그인해 서버에 저장된 기록을 확인할 수 있습니다. 기존 데이터 검증 및 계정 동기화용 파서는 유지합니다.

## Firebase 운영과 로컬 테스트

프로젝트: `saitama-workout-ff2d5`, Spark, Firestore Standard 서울(`asia-northeast3`). 공개 웹 설정은 `src/cloud/firebaseConfig.js`에 있습니다. 공개 설정값은 인증 비밀키가 아니며 접근 권한은 `firestore.rules`로 제한합니다. 서비스 계정 키는 프런트엔드나 저장소에 넣지 않습니다.

- Authentication: Google 및 서버 검증 카카오 Custom Token을 사용합니다. 승인 도메인에 `saitama-workout.vercel.app`, `wkdeogh.github.io`, `localhost`를 등록합니다.
- Firestore: `accounts/{uid}`는 본인만 읽고 쓸 수 있습니다. 원본 운동 기록은 검증된 JSON 문자열로 보관합니다(앱 동기화 상한 850KB).
- `rankings/{uid}`는 로그인 사용자만 읽을 수 있고, 본인만 수정·삭제합니다. 계정 기록과 공개 요약은 한 트랜잭션으로 반영합니다. 참여/중단 선택은 제공하지 않으며, 기존 미참여 계정도 다음 접속 시 이름 설정 후 자동 등록됩니다.
- `firestore.indexes.json`에 주간 순위용 복합 색인과 큰 payload 필드의 색인 제외를 정의했습니다. 규칙/색인 변경은 권한 있는 Firebase CLI 로그인 후 `npx firebase deploy --only firestore`로 별도 배포합니다. GitHub Actions는 앱 배포만 수행합니다.
- 랭킹은 자기 신고 운동량 기준입니다. 규칙은 소유권·필드·범위·종목 합계와 EXP 일치를 검증하지만 실제 운동 여부나 클라이언트 조작을 완전히 방지하지 않습니다. 서버 재계산/부정행위 방지가 필요하면 별도 신뢰 가능한 백엔드가 필요합니다.
- 실시간 구독 없이 화면 진입/새로고침에 최대 50명을 조회합니다. 기록 저장 시 자동 동기화하며 서버 사용량 제한 오류는 재시도 루프 없이 표시합니다. 서버 요약은 해당 사용자의 마지막 동기화 시점 기준이며 미기록 레벨 감소는 조회 시 추가 계산합니다.

에뮬레이터 테스트는 프로덕션과 완전히 분리합니다:

```sh
npm run emulators
# 다른 터미널에서:
cp .env.example .env.local
npm run dev
```

Google 로그인 팝업에 에뮬레이터 전용 가상 계정을 생성합니다. 테스트 후 `.env.local`을 제거하면 실제 프로젝트 설정을 사용합니다. 에뮬레이터 연결은 개발 모드에서만 허용됩니다.

상단 설정 옆 ? 버튼에서 6페이지 사용 가이드를 열 수 있습니다. 운동 기록, 성장, 친구·랭킹, 오운완 공유, 아이폰·갤럭시 홈 화면 추가를 안내합니다. 이름 설정 후 계정별로 이 브라우저에서 최초 1회 자동 표시하며 좌우 스와이프와 이전·다음 버튼을 지원합니다.

## 카카오 로그인 운영

카카오 앱 ID: `1589345`. 로그인 사용 설정 ON, REST API 키의 리다이렉트 URI는 `https://saitama-workout.vercel.app/api/auth/kakao/callback`입니다. 이메일·닉네임 등 추가 동의항목 없이 카카오 회원번호만 사용합니다. 로그인 버튼은 [카카오 공식 리소스](https://developers.kakao.com/tool/resource/login)를 사용합니다.

Vercel **Production 전용 Secret 환경 변수**:

- `KAKAO_REST_API_KEY`: 카카오 REST API 키
- `KAKAO_CLIENT_SECRET`: 해당 REST API 키의 카카오 로그인 Client Secret
- `FIREBASE_SERVICE_ACCOUNT_JSON`: 같은 Firebase 프로젝트의 Admin SDK 서비스 계정 JSON 전체
- `KAKAO_LOGIN_ENABLED`: `true` (키 등록과 Firestore 규칙 배포 후 활성화)
- `AUTH_ORIGIN`: 생략 시 `https://saitama-workout.vercel.app` 고정. 다른 정식 주소로 이전할 때만 변경하고 카카오 리다이렉트도 함께 갱신합니다.

위 값에는 `VITE_` 접두사를 붙이지 않습니다. 서비스 계정 JSON은 `.gitignore`로 제외하며 저장소에 커밋하지 않습니다. 키가 없거나 비활성화 상태이면 카카오 버튼은 준비 중으로 표시되고 Google 로그인은 유지됩니다. 환경 변수 변경 후 재배포해야 적용됩니다. Vite 로컬 서버에는 `/api`가 없으므로 전체 OAuth 검증은 정식 Vercel 배포에서 수행합니다.

`api/auth/kakao/[action].js`와 `server/`에서 인가 코드 교환·회원번호 조회·Firebase Custom Token 발급을 처리합니다. OAuth state는 10분 유효한 서명된 Secure/HttpOnly/SameSite 쿠키에 묶이며, 토큰은 URL에 넣지 않고 60초 유효한 HttpOnly 쿠키를 same-origin POST로 교환합니다. 카카오 액세스/리프레시 토큰과 이메일·프로필은 보관하지 않습니다. 브라우저에서 받은 임의 UID나 이메일로 계정을 연결하지 않습니다.

기존 Google 사용자는 **설정 → 카카오 계정 연결**에서 Google 재인증 후 카카오에 동의해야 같은 UID로 연결됩니다. 이미 다른 앱 계정에 연결된 카카오는 연결을 거절하며 기록 자동 병합은 하지 않습니다. `kakaoIdentities/{회원번호}`와 `authLinks/{uid}`는 서버만 접근하며 트랜잭션으로 일대일 연결을 보장합니다. 카카오로 먼저 가입하면 별도 계정이므로, 기존 기록을 사용할 사람은 Google 로그인부터 해야 합니다. 카카오 신규 계정에는 이후 Google 연결·계정 간 기록 병합 UI를 제공하지 않습니다.

Firestore는 `google.com` 또는 서버가 발급한 `custom` 인증 + `kakao: true` 클레임만 허용합니다. 일반 custom/anonymous 인증과 다른 사용자의 기록 접근은 거절합니다. `npm test`는 OAuth state·origin·재인증·오류 흐름을 검증하고 `npm run test:rules`는 Google/Kakao 계정 격리를 검증합니다.

## 오운완 인증 이미지

오늘의 훈련에서 ‘오운완’을 누르면 입력 중인 운동량을 먼저 저장하고, 그 기록과 갱신된 레벨로 1080×1440 PNG를 생성합니다. 날짜·이름·레벨·푸쉬업·스쿼트·기타운동·달리기·앱 주소가 한 이미지에 포함됩니다. 목표를 전부 채우지 않았어도 실제 운동 기록이 있으면 사용할 수 있습니다.

캐릭터는 세 가지 포즈 중 무작위로 등장하며 ‘다른 포즈’로 변경할 수 있습니다. 이미지는 기기 안에서 생성하고 서버에 업로드하지 않습니다. ‘공유’는 Web Share API로 PNG와 앱 링크를 함께 전달하며, 카카오톡 등 공유 대상은 기기에 설치된 앱과 브라우저 지원 여부에 따라 달라집니다. 공유 앱이 텍스트·링크를 생략할 수 있어 이미지에도 주소를 넣고, 이미지 저장·앱 링크 복사를 제공합니다. 실제 수신 앱까지의 전달은 해당 기기에서 확인해야 합니다.

## 친구·계정 태그·푸시 알림

‘친구’ 탭은 전체 랭킹과 친구 랭킹을 함께 제공합니다. 기존 전체 랭킹의 누적/주간 EXP 정렬·동점 순위·상위 50명·캐릭터 상세 보기는 유지합니다. 친구 랭킹은 나와 수락된 친구만 포함하며 실제 기록에서 현재 EXP와 레벨을 계산합니다.

- `socialProfiles`/`socialTags`: 서버 트랜잭션으로 랜덤 `ST-XXXXXXXX` 태그를 한 번 발급합니다. 닉네임을 바꿔도 태그는 유지됩니다. 신규 계정은 최초 로그인 시 발급되며 기존 계정도 접속 시 누락된 태그를 자동 보완합니다. 기존 계정 일괄 발급도 완료했습니다.
- 닉네임·태그 입력 후 300ms 동안 입력이 멈추면 자동 검색합니다. 한글 조합 중에는 기다리며, 태그도 대소문자·앞의 `#`와 관계없이 앞부분 검색을 지원합니다. 같은 닉네임은 검색 결과의 태그로 구분하고 랭킹 목록에는 닉네임만 표시합니다.
- 친구 요청은 서버에서만 생성/수락/거절/취소합니다. 양방향 친구 목록과 요청 수를 원자적으로 갱신하고, 다른 사용자의 요청 처리·중복 요청·역방향 중복을 차단합니다. 최대 친구 200명, 대기 요청 100건, 요청 20회/일, 거절·취소 후 같은 상대에게 재요청은 24시간 이후입니다.
- `friendInbox/{uid}`는 본인만 실시간 조회할 수 있습니다. 나머지 친구 데이터 및 푸시 토큰은 서버 전용이며 클라이언트가 직접 읽거나 변경할 수 없습니다. 모든 `/api/friends/*` 요청은 Google/Kakao Firebase ID 토큰과 같은 출처 검증을 거칩니다.
- FCM v1과 Firebase 웹 푸시 인증서를 사용합니다. 공개 VAPID 키는 `pushClient.js`, 서버 인증은 기존 `FIREBASE_SERVICE_ACCOUNT_JSON`을 사용합니다. 새 비공개 키나 유료 Firebase Functions는 필요하지 않습니다.
- 친구 탭의 ‘알림 켜기’에서 사용자가 허용한 기기에 푸시를 보냅니다. iOS/iPadOS 16.4 이상은 홈 화면에 추가한 웹앱에서 허용해야 합니다. 서비스 워커는 페이지/운동 기록을 캐시하지 않습니다. 알림을 누르면 친구 탭으로 이동합니다. 계정별 기기 5개까지 등록하며, 로그아웃 시 구독을 해제하고 기기의 알림 수신 계정을 지웁니다.
- 알림 거부/미지원/전송 실패여도 받은 요청 목록과 앱 안 배지는 유지됩니다. 실제 휴대폰의 백그라운드 푸시 도착 여부는 그 기기에서 권한을 허용한 후 확인해야 합니다.

검증: `npm run check` 및 `npm run test:rules`(친구 서버 트랜잭션·권한·중복/취소/거절·푸시 실패 테스트 포함). 운영 계정끼리의 테스트 요청은 생성하지 않습니다.

### 랭킹 오늘 활동

닉네임 아래 `▲ 오늘 EXP`를 표시합니다. 한국 시간 기준 오늘 저장된 실제 운동량을 계산하며 0~99 EXP는 회색, 이후 매 100 EXP 구간마다 다른 색상입니다. 상세 팝업에는 종목별 오늘 증가분을 표시합니다. 전체·친구 랭킹 모두 서버에서 오늘 합계만 추가 조회하고, 계정 원본과 과거 날짜별 기록은 공개하지 않습니다. 자정 또는 앱 복귀 시 날짜를 갱신하며 이전 날짜의 증가분은 0으로 표시합니다. 누적·주간 순위 산정은 유지됩니다.

### 가상 훈련생과 관리자

- 설정의 관리자 페이지는 `wkdeoghq@gmail.com`의 Firebase 계정에만 표시됩니다. 연결된 카카오 로그인도 같은 UID이면 사용할 수 있습니다. API는 서버에서 Google 연결·이메일 인증을 확인한 관리자 계정 UID와 로그인 UID를 비교하며, 클라이언트가 넘긴 이메일이나 UID로 권한을 부여하지 않습니다.
- `virtualTrainees`는 서버 전용이며 실제 Firebase 로그인 계정을 만들지 않습니다. `고구마똥` 한 명을 고정 ID로 생성하고, 일반 태그·친구 관계·전체/친구 랭킹에 연결합니다. 닉네임에 배지를 붙이지 않고 랭킹 안내에서 가상 경쟁자 참여를 알립니다.
- 관리자에서 누적 종목별 운동량·현재 레벨·누적 EXP를 각각 수정하고 자동 운동을 켜거나 끌 수 있습니다. 동시 수정은 revision으로 막고 변경 내역은 서버 전용 `adminAudit`에 남깁니다. 직접 지정한 EXP/레벨은 운동량과 독립적인 시뮬레이션 값입니다.
- 한국 시간 매일 21시 예약 실행: 푸쉬업/스쿼트 각 10개 단위, 운동일 80~120 EXP, 3일 묶음마다 무작위 하루 휴식. 자동 운동을 끄면 운동은 추가되지 않으며 미운동 레벨 감소가 적용됩니다.
- `CRON_SECRET`을 Vercel Production의 Secret 환경 변수로 등록해야 합니다. `/api/cron/virtual-workouts`는 일치하는 Bearer 키가 없으면 거부합니다. Vercel Hobby의 실행 시간 오차를 허용하며, 랭킹 조회 시에도 예정 시간이 지난 작업을 보충합니다. 날짜별 결정적 추첨과 Firestore transaction으로 중복 반영하지 않습니다.
- 관리자 목록에서 최초 `고구마똥 추가` 버튼으로 생성할 수 있습니다. 생성은 반복 호출해도 한 명만 유지됩니다. 추가된 훈련생은 친구 요청을 즉시 수락합니다.

## 연속 운동 보상

하루에 1 EXP 이상 운동한 연속 일수를 사용하며 전부 0인 기록은 제외합니다. 오늘 운동 기록 전에는 어제까지의 연속 일수를 유지하고, 하루를 놓치면 초기화됩니다. 10/20/30/40/50/60일마다 주황빛 황금/빨강/보라/노랑/파랑/황금 오라를 받으며 60일 이상은 6단계를 유지합니다. 30~49일에는 불꽃 눈, 50일 이상에는 더 큰 청록색 불꽃 눈빛이 표시됩니다. 오라와 눈 효과는 레벨과 무관하며, 링·번개·주먹 에너지·체형·머리·의상은 기존 레벨 기준입니다. 캐릭터 카드와 오운완 이미지에 연속 일수와 현재 보상이 반영됩니다.
