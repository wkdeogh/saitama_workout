# 싸이따마훈련소

푸쉬업·스쿼트·윗몸일으키기·달리기 기록, 월별 캘린더, Three.js 캐릭터 성장. 모바일 우선 웹 앱입니다. GitHub Pages에서 호스팅하고 Firebase Authentication과 Firestore를 사용합니다.

- Google 로그인 후 최초 접속 시 캐릭터 이름(1~20자)을 입력합니다. 설정에서 변경할 수 있으며 로컬 저장과 JSON 백업에 포함됩니다. 이름 없는 기존 기록은 유지한 채 이름을 설정합니다. 백업 합치기는 현재 이름을 유지하고, 전체 교체는 백업 이름을 사용합니다(이름 없는 백업은 현재 이름 유지).
- 신규 계정의 기본 목표: 푸쉬업·스쿼트·윗몸일으키기 각각 100개, 달리기 10km. 설정에서 변경할 수 있으며 기존 개인 목표와 과거 날짜의 목표는 유지합니다. 예전 기본값(50·50·0·0)을 그대로 쓰던 계정은 다음 접속 시 오늘 목표부터 한 번만 새 기본값으로 전환합니다. 이후 개인이 다시 변경한 목표는 그대로 유지합니다. 목표와 관계없이 실제 운동량으로 EXP를 얻습니다.
- 날짜별 실제 횟수와 거리(0.1km 단위) 입력·수정·삭제. 달성 여부는 그 날짜에 저장된 목표로 계산합니다.
- Google 로그인이 필수입니다. 운동 기록과 이름은 Firestore에 계정별로 저장하고, `localStorage`의 `saitama-training:v1:account:{uid}`에 동기화 기준과 함께 캐시합니다. 비로그인 기록을 자동으로 가져오지 않습니다.
- 하단 메뉴는 훈련소·운동 기록·성장 도감·랭킹입니다. 설정과 백업은 상단에서 엽니다.
- 이름 설정을 마친 로그인 사용자는 자동으로 랭킹에 등록됩니다. 캐릭터 이름, 레벨, EXP와 종목별 누적 운동량이 다른 로그인 사용자에게 공개됩니다. 누적(기본 탭)·주간(한국 시간 월요일 시작) EXP 상위 50명, 동점은 공동 순위입니다. 1~3위에는 금·은·동 트로피가 표시되며 레벨을 크게, EXP를 작게 표시합니다. 순위는 EXP 기준입니다. 사용자 행이나 내 캐릭터 요약을 누르면 캐릭터와 누적 운동량 팝업이 열립니다. 이메일과 날짜별 기록은 랭킹에 공개하지 않습니다.
- JSON 백업: 내보내기, 유효성 검사, 합치기/전체 교체 미리보기. 합치기는 같은 날짜를 백업 내용으로 교체하고 현재 목표는 유지합니다.
- iOS 홈 화면용 180px 아이콘, Android용 192/512px 아이콘과 웹 앱 매니페스트를 포함합니다.

## 성장 규칙

레벨 1에서 시작하여 **100 EXP마다 1레벨 상승**, 최대 **1000레벨**입니다.

- 푸쉬업·스쿼트·윗몸일으키기: 1회 = 1 EXP
- 달리기: 0.1km = 1 EXP (5km = 50 EXP)
- 예: 푸쉬업 50회 + 스쿼트 50회 = 100 EXP, 1 → 2레벨. 여기에 윗몸일으키기 50회 + 달리기 5km를 더하면 200 EXP, 1 → 3레벨.
- 기존 기록과 버전 1 JSON 백업도 실제 운동량 기준으로 자동 환산합니다. 추가 종목은 0으로 전환하며 과거 목표 달성은 유지합니다. 새 데이터/백업은 버전 2를 사용합니다.

마지막 운동 이후 **연속 미기록 5일마다 5레벨 하락**, 최저 1레벨입니다. 기록한 당일은 공백에 포함하지 않습니다. 예: 9월 1일 운동 후 9월 6일까지 미기록이면 −5레벨. 9월 6일 운동하면 공백은 4일이므로 해당 감소는 취소됩니다. 9월 7일에 재개하면 중간 5일 공백으로 감소가 유지됩니다. 10일 공백이면 −10레벨입니다. 네 종목 중 1 EXP 이상 기록하면 미기록 기간이 초기화됩니다. 전부 0인 기록은 운동으로 계산하지 않습니다.

다음 레벨까지 쌓은 EXP 나머지는 하락해도 유지됩니다. 최고 레벨에서는 초과 EXP를 비축하지 않습니다. 기록 수정·삭제·복원 시 모든 이력을 날짜순으로 다시 계산합니다. 누적 EXP는 운동량 총합이므로 레벨 감소와 관계없이 유지됩니다. 기기의 로컬 날짜를 사용합니다.

1레벨은 작은 키와 가는 팔다리로 시작하며 매 레벨 키·어깨·팔다리가 성장합니다. 가슴 근육(20), 복근(30), 등과 승모근(45), 황금 오라(60), 에너지 링(80), 불꽃 눈(100), 전신 번개(120), 붉은 오라와 주먹 에너지(150), 보라색 오라(175)를 해금합니다.

200부터 머리카락이 자라며 삼중 링이 생깁니다. 손목 보호대(250), 솟은 머리와 수련 반바지(350), 주황 바지와 푸른 부츠(450), 허리띠와 매듭(550), 도복 상의(650), 금빛 머리와 청록 눈빛(750), 금발 각성과 황금 오라(850), 최종 첨탑 머리와 사중 링(1000)으로 진화합니다. 머리 길이와 체격은 중간 레벨에서도 연속적으로 변화합니다.

성장 도감의 단계를 누르면 팝업으로 외형을 확인합니다. 잠긴 단계는 어두운 실루엣으로 가리고, 현재 레벨로 해금한 단계만 선명하게 표시합니다. 자유로운 레벨별 미리보기는 제공하지 않습니다. 동일한 WebGL 렌더러를 재사용하며 화면 밖과 숨겨진 탭에서는 렌더링을 멈춥니다. 동작 줄이기 설정에서는 이펙트를 정지된 상태로 표시합니다.

## 개발

Node.js 22 이상 권장.

```sh
npm ci
npm run dev
npm run check
```

`npm test`는 기록, 날짜, 백업, 레벨, 계정 병합과 랭킹을 검증합니다. `npm run test:rules`는 Java 21 이상이 필요하며 Firestore 에뮬레이터에서 계정 격리, Google 인증 필수, 랭킹 쓰기 검증을 수행합니다. `npm run build` 출력은 `dist/`입니다.

## GitHub Pages

[Vite 공식 배포 방식](https://vite.dev/guide/static-deploy#github-pages)에 따라 저장소의 Settings → Pages → Source를 **GitHub Actions**로 설정합니다. `main` 푸시 때 `.github/workflows/deploy.yml`에서 테스트·빌드 후 배포합니다. PR에서는 검증만 수행합니다.

서비스 경로: `https://wkdeogh.github.io/saitama_workout/`

## 저장과 백업

같은 Google 계정으로 로그인하면 서버에 저장된 기록을 불러옵니다. 수정은 기기에 먼저 저장한 후 서버 트랜잭션으로 동기화합니다. 서로 다른 날짜의 수정은 합치고, 같은 날짜를 동시에 수정하면 마지막 동기화의 변경이 우선합니다. 실패하면 기기 기록을 보존하고 설정/랭킹의 동기화 버튼으로 재시도합니다. 동기화가 끝나기 전 브라우저 데이터를 삭제하지 마세요. JSON은 별도 백업으로 계속 사용할 수 있습니다. 시크릿 브라우저에서는 기록이 유지되지 않을 수 있습니다. 네트워크 없이 앱을 다시 여는 오프라인 캐시는 별도로 제공하지 않습니다.

잘못된 저장 데이터를 감지하면 덮어쓰기를 막고 원본 내보내기와 정상 백업 복원을 제공합니다. 가져오기는 2MB 이하, 지원 버전, 날짜, 정수 횟수, 0.1km 단위 거리와 목표를 검증합니다.

## 이미지

아이콘 프롬프트: "제공된 치비 사이타마의 대머리 얼굴·무표정한 눈·빨간 주먹·노란 옷·흰 망토를 유지한 정사각형 앱 아이콘. 얼굴과 주먹 중심, 굵은 만화선, 오렌지 배경, 글자와 테두리 없이 전체 영역 사용."

## Firebase 운영과 로컬 테스트

프로젝트: `saitama-workout-ff2d5`, Spark, Firestore Standard 서울(`asia-northeast3`). 공개 웹 설정은 `src/cloud/firebaseConfig.js`에 있습니다. 공개 설정값은 인증 비밀키가 아니며 접근 권한은 `firestore.rules`로 제한합니다. 서비스 계정 키는 프런트엔드나 저장소에 넣지 않습니다.

- Authentication: Google만 사용. 승인 도메인에 `wkdeogh.github.io`와 `localhost`를 등록합니다.
- Firestore: `accounts/{uid}`는 본인만 읽고 쓸 수 있습니다. 원본 운동 기록은 검증된 JSON 문자열로 보관합니다(앱 동기화 상한 850KB).
- `rankings/{uid}`는 로그인 사용자만 읽을 수 있고, 본인만 수정·삭제합니다. 계정 기록과 공개 요약은 한 트랜잭션으로 반영합니다. 참여/중단 선택은 제공하지 않으며, 기존 미참여 계정도 다음 접속 시 이름 설정 후 자동 등록됩니다.
- `firestore.indexes.json`에 주간 순위용 복합 색인과 큰 payload 필드의 색인 제외를 정의했습니다. 규칙/색인 변경은 권한 있는 Firebase CLI 로그인 후 `npx firebase deploy --only firestore`로 별도 배포합니다. GitHub Actions는 앱 배포만 수행합니다.
- 랭킹은 자기 신고 운동량 기준입니다. 규칙은 소유권·필드·범위·종목 합계와 EXP 일치를 검증하지만 실제 운동 여부나 클라이언트 조작을 완전히 방지하지 않습니다. 서버 재계산/부정행위 방지가 필요하면 별도 신뢰 가능한 백엔드가 필요합니다.
- 실시간 구독 없이 화면 진입/새로고침에 최대 50명을 조회합니다. 기록 저장 시 자동 동기화하며 서버 사용량 제한 오류는 재시도 루프 없이 표시합니다. 서버 요약은 해당 사용자의 마지막 동기화 시점 기준이며 미기록 레벨 감소는 조회 시 추가 계산합니다.

에뮬레이터 테스트는 프로덕션과 완전히 분리합니다:

```sh
npm run emulators
# 다른 터미널에서:
cp .env.example .env.local
npm run dev
```

Google 로그인 팝업에 에뮬레이터 전용 가상 계정을 생성합니다. 테스트 후 `.env.local`을 제거하면 실제 프로젝트 설정을 사용합니다. 에뮬레이터 연결은 개발 모드에서만 허용됩니다.

상단 설정 옆 ? 버튼에서 운동 기록, EXP와 감소 규칙, 랭킹, 백업 및 아이폰 Safari·갤럭시 Chrome/삼성 인터넷 홈 화면 추가 도움말을 확인할 수 있습니다.
