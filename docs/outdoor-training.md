# 야외 훈련장

탭에서 내 캐릭터를 확인한 뒤 `입장하기`를 누르면 전체 화면으로 월드에 들어갑니다. 우상단 `나가기` 또는 Esc로 돌아옵니다. 실제 운동 기록, 목표, 경험치, 계정 데이터는 수정하지 않습니다.

- PC 이동: WASD / 방향키. 화면을 드래그하거나 Q/E, 시점 버튼으로 카메라를 회전합니다.
- 모바일 이동: 좌하단 조이스틱. 다른 손가락으로 화면을 드래그해 카메라를 돌릴 수 있습니다.
- 푸쉬업 / 스쿼트: 누르면 반복, 다시 누르거나 이동하면 중단합니다.
- 달리기: 토글 버튼 또는 R. 켜져 있으면 이동할 때 달립니다.
- 울타리 안 훈련장은 34×20m로 기존 면적의 약 2배입니다. 벤치프레스·스미스머신과 철봉·평행봉·벤치·매트를 배치했고, 바깥에 3개 레인의 순환 달리기 트랙을 두었습니다. 기구와 울타리의 충돌 경계는 같은 배치 정보에서 계산합니다.
- 걷기·달리기는 고정된 팔다리 길이로 관절을 움직입니다. 달리기는 팔꿈치를 굽혀 다리와 반대로 흔들고, 지지발·무릎 회수·발목 굴림과 몸의 전방 기울기를 반영합니다.
- 채팅: 80자, 전송 간격 2초, 머리 위 말풍선 5초. 채팅 내역 목록은 저장하지 않습니다.
- 다른 캐릭터의 닉네임과 말풍선은 8m 이내에서 선명하게 보이며 8~10m에서 흐려지고 10m 이상에서는 숨깁니다. 캐릭터 자체와 본인의 닉네임은 이 거리 제한을 받지 않습니다.
- 모두 하나의 `worlds/meadow/players` 필드에 접속합니다. 로그인 계정은 기존 인증을 사용하고 비회원은 별도의 Firebase 앱에서 익명 인증합니다. 비회원 접속이 기존 운동기록 계정의 로그인 상태를 바꾸지 않습니다.

## 운영 연결

2026-11-03 기존 Firebase 프로젝트의 싱가포르(asia-southeast1) 리전에 기본 Realtime Database를 생성하고, `database.rules.json` 게시와 익명 인증 활성화를 완료했습니다. 실제 Firebase의 비회원 접속·동기화와 기존 운동기록 접근 차단을 확인했습니다. 공개 웹 설정인 운영 Database URL은 `fieldClient.js`에 기본값으로 연결하며, 다른 인스턴스를 쓸 때는 `VITE_FIREBASE_DATABASE_URL`로 덮어씁니다. 에뮬레이터 모드에서는 운영 DB에 연결하지 않습니다. 연결이 실패하면 화면에 연결 상태를 표시하며 다른 사람과 연결됐다고 표시하지 않습니다.

1. 기본 URL은 `https://saitama-workout-ff2d5-default-rtdb.asia-southeast1.firebasedatabase.app`입니다. 다른 프로젝트·DB를 사용할 때만 배포 환경의 `VITE_FIREBASE_DATABASE_URL`을 등록합니다.
2. Firebase Authentication의 로그인 제공자에서 `익명`을 활성화합니다. 기존 Google / 카카오 제공자는 유지합니다.
3. `database.rules.json`의 규칙을 해당 인스턴스에 배포합니다. 기본 인스턴스는 `npx firebase deploy --only database --project saitama-workout-ff2d5`를 사용합니다. 별도 인스턴스는 Firebase deploy target을 먼저 지정합니다. 기존 Firestore 규칙은 변경하지 않습니다.
4. Vite 환경 변수는 빌드 시 반영되므로 앱을 새로 빌드해 배포합니다. 비회원 두 기기로 입장·이동·대화·퇴장을 확인합니다.

Realtime Database 사용량과 동시 연결 한도는 프로젝트 요금제에 따라 달라집니다. 유료 요금제 전환은 이 구현에 포함하지 않습니다.

## 동기화와 수명

`players/{uid}/{sessionId}`에는 공개 이름·레벨·연속 운동일·비회원 여부, 월드 좌표·방향·동작, 마지막 메시지와 시각만 보냅니다. 각 탭은 별도 세션이므로 한 탭에서 나가도 다른 탭은 유지합니다. 120ms 간격으로 이동 상태를 전송하고, 가만히 있을 때는 12초마다 접속 상태만 갱신합니다. 다른 캐릭터는 프레임 사이를 보간해 움직입니다.

서버에 `onDisconnect().remove()`를 등록한 뒤 입장 정보를 씁니다. 퇴장 시 쓰기 완료 뒤 세션을 제거하고 구독·타이머·WebGL 자원을 해제합니다. 연결이 끊어진 캐릭터는 서버에서 제거하며 45초 넘게 갱신되지 않은 세션도 화면에서 제외합니다. 서버에는 세션의 최신 메시지만 있으며, 퇴장 또는 연결 종료 시 세션과 함께 삭제합니다.

## 로컬 검증

Java 21 이상과 Node 24가 필요합니다. `.env.example`의 데모 인증 설정을 사용하고 운영 프로젝트와 분리합니다.

```sh
npx firebase emulators:start --project demo-saitama --only auth,database
npm run dev
```

다른 터미널에서 `npm run check`, `npm run test:field`를 실행합니다. 에뮬레이터가 이미 실행 중이라면 `FIREBASE_DATABASE_EMULATOR_HOST=127.0.0.1:9000 node --test tests/field/*.test.js`로 규칙 검사를 실행합니다. 에뮬레이터 테스트와 브라우저는 서로 다른 DB 네임스페이스를 사용하므로 테스트 데이터가 화면에 섞이지 않습니다.

브라우저에서는 390px / 320px / 가로 화면, 드래그·조이스틱 해제, 운동 중 이동, 달리기 토글, 두 비회원의 만남과 말풍선, 퇴장 후 접속 인원 감소, 운동 기록 불변을 확인합니다.
