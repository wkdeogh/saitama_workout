# 개인정보 문의·삭제 운영 절차

공개 방침: `public/privacy.html`. 운영자·개인정보 보호 담당자: 장대호 / `wkdeoghq@gmail.com`.

현재 계정 삭제 API와 전체 삭제 버튼은 없다. 이 문서는 담당자가 수동으로 요청을 처리하기 위한 절차이며, 실제 계정이나 데이터를 삭제하는 실행 스크립트가 아니다. 개인정보 삭제 요청은 별도 운영 권한으로 처리한다.

## 문의 접수와 본인 확인

1. 요청 유형(열람·정정·삭제·처리정지), 계정 로그인 방식·캐릭터 이름·태그를 확인한다. 닉네임·태그는 공개되므로 이것만으로 본인 확인을 완료하지 않는다.
2. Google 계정은 Firebase Authentication에 등록된 이메일과 요청자의 접근 가능 여부를 확인한다. 카카오 단독 계정에는 이메일이 없을 수 있으므로, 인증된 계정에서의 확인 등 안전한 별도 절차를 협의한다. 필요한 최소 정보만 받고 비밀번호·ID 토큰·카카오 토큰·신분증 사본을 이메일로 요구하지 않는다.
3. 적용 법령에 맞는 기한과 처리 방법을 안내한다. 대리인의 요청은 대리 권한도 확인한다. 전체 삭제 전에는 기록 복구 불가와 기기 저장 데이터가 별개임을 알린다.
4. 처리 결과를 본인에게 회신한다. 본인 확인 자료와 문의 메일은 필요한 후속 확인 종료 후 삭제하며, 법적 별도 보관이 필요하면 근거·항목·기간을 안내한다. 임의의 영구 보관을 하지 않는다.

## 계정 전체 삭제 시 확인 범위

서버 작업 전 UID와 계정 태그·카카오 연결을 확인한다. 클라이언트용 Firestore 규칙은 계정 삭제를 허용하지 않으므로 담당자의 Firebase 관리 권한으로 수행한다. 현재 로그인 세션이 기록을 다시 동기화하지 않도록 이용자에게 로그아웃을 안내하고, 계정을 비활성화·세션 취소한 뒤 기존 인증 토큰이 더 이상 쓰이지 않는 것을 확인한다. 인증 계정 삭제만 먼저 처리하고 서비스 데이터를 남겨두지 않는다.

| 대상                                                  | 필요한 처리                                                                                                                                                                                                                                                                                                                                                                   |
| ----------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `accounts/{uid}`, `rankings/{uid}`                    | 원본 기록·동기화 정보와 공개 랭킹 문서 삭제                                                                                                                                                                                                                                                                                                                                   |
| `socialProfiles/{uid}`, `socialTags/{tag}`            | 닉네임·태그 프로필과 역방향 매핑 삭제                                                                                                                                                                                                                                                                                                                                         |
| `friendRequests`                                      | `from` 또는 `to`가 대상 UID인 요청 삭제. 상대의 `friendInbox` 대기·발신 수를 일관되게 갱신                                                                                                                                                                                                                                                                                    |
| `friendLists`                                         | 모든 상대 목록에서 대상 UID 제거. 대상 계정의 목록 삭제. 가상 훈련생 목록과 관계도 포함                                                                                                                                                                                                                                                                                       |
| `friendInbox/{uid}`                                   | 요청 목록 카운터·일별 요청 제한·시각 정보 삭제                                                                                                                                                                                                                                                                                                                                |
| `friendCooldowns`                                     | 문서 ID가 두 UID의 해시이고 본문에는 시각만 있으므로 UID 부분 문자열 검색으로 찾을 수 없음. 삭제 전 Authentication·계정·소셜 프로필·가상 훈련생의 상대 UID 목록을 확보하고, `server/friendsModel.js`의 `pairKey(대상 UID, 상대 UID)`로 키를 재계산하여 존재하는 제한 문서 삭제. 이미 제거된 상대가 있어 식별할 수 없는 레거시 문서는 별도 보관 필요성 검토·정리 대상으로 기록 |
| `pushDevices`                                         | `uid`가 대상 UID인 모든 기기 토큰 문서 삭제                                                                                                                                                                                                                                                                                                                                   |
| `authLinks/{uid}`, `kakaoIdentities/{카카오회원번호}` | 카카오 연결 정보와 역방향 매핑 삭제                                                                                                                                                                                                                                                                                                                                           |
| Firebase Authentication                               | 대상 UID의 사용자 삭제, 연결된 Google/Kakao 인증 정보 정리                                                                                                                                                                                                                                                                                                                    |
| `adminAudit`                                          | 대상이 관리자 계정인 경우 actor UID를 포함한 로그 확인. 법적으로 별도 보관할 근거가 없다면 삭제 또는 식별 불가능하게 처리                                                                                                                                                                                                                                                     |

대량 문서는 Firebase 작업 한도를 지키며 나누어 처리한다. 관계 문서 갱신은 트랜잭션 등으로 상대 이용자의 다른 관계·요청을 보존한다. Firestore TTL이 설정되어 있다고 가정하지 않는다. 읽기 전에 현재 스키마를 확인한다.

작업 후 공개 `/api/rankings`, 친구 검색·목록, 직접 문서 조회에서 대상 데이터가 남지 않았는지 확인한다. 로그인 세션·캐시·기록 동기화로 재생성되지 않았는지도 확인한다. 본인의 기기 저장 데이터는 이용자에게 사이트 데이터 삭제 방법을 안내하고, 다른 이용자의 이미 저장·공유된 이미지까지 삭제되었다고 주장하지 않는다. 제공자 관리 로그·백업의 지연 삭제는 공급자 정책에 따라 결과 안내에 포함한다.

## 운영 전·변경 시 점검

- 배포한 `/privacy.html`이 로그인 없이 읽히는지 확인한다. 앱 링크와 메일 주소를 확인한다.
- 저장소 문서는 Firestore 서울 리전(`asia-northeast3`)을 기록하고 있다. 개인정보 방침 공개 전 Firebase 콘솔의 실제 데이터베이스 위치를 대조한다. 이번 로컬 점검에서는 Firebase CLI 인증이 없어 실시간 조회를 완료하지 못했다. 다른 리전이면 방침을 수정한다.
- Google Auth 미국 처리 외의 FCM·Gmail·Vercel 글로벌 처리에 대해 현재 계약·설정·하위 처리자를 확인하고, 법적으로 필요한 국외이전 고지(국가·수탁자 연락처·시기·방법·기간·거부 영향)와 별도 동의 여부를 실제 운영에 맞춰 확정한다. 공개 방침의 공급자 링크만으로 별도 동의를 대신하지 않는다.
- Vercel 로그 보관은 사용 플랜·Observability 설정, Firebase 백업은 운영 설정에 따라 확인한다. 활성화하지 않은 Analytics·Crashlytics·백업을 사용한다고 안내하지 않는다.
- 실제 AdSense 활성화 시 방침의 현재 비활성 상태 문구를 갱신하고, 추가 광고 제공자와 필요한 CMP·동의 수단을 점검한다. 광고 ID만 입력하여 활성화하기 전에 이 작업을 완료한다.
- 새 수집 항목·제공자·처리 목적을 추가하면 시행일과 방침을 갱신하고 필요한 안내·동의 절차를 적용한다.
